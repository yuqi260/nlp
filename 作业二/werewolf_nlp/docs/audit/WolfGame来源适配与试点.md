# WolfGame 跨来源对局适配和试点

## 目的与限制

对现有身份预测流程进行跨日志格式的可行性检查。WolfGame 的角色数量相同，但包含警长竞选、警徽、1.5 票、PK 和屠边等规则；与 MaKTO 的原规则不完全一致。生成的玩家使用 Qwen3.5-27B，并不是独立的人类游戏数据，且一天上限人为截断。一次样本不能用于判断泛化准确率。

候选源为 `data/raw/wolfgame_candidate`，上游提交 `d3068b92c087953cc74d479237e66e19aa04ce68`。隔离环境只用于该候选引擎。运行 `scripts/generate_wolfgame_pilot.py` 默认 dry run；显式 `--execute` 才产生付费模型调用，密钥由环境变量获取，不写入配置文件。

## 公开信息与标签

`src/werewolf_nlp/wolfgame_adapter.py` 将公开事件转换为逐日快照，结束公告和全员身份公布之前截断。公开名册确定分析用 player_id，角色标签按姓名单独关联；该编号不是原座位。原始 `seat_ref` 是引擎开局赋值且属于 public_snapshot 的公开字段；转换器只从终局文件取这一固定公开字段及标签，不读取终局存活状态、阵营、夜间行动或私有推理。名字与内部 ID 的关联只从当前及过去的公开发言和投票中建立，匹配不明确时失败，不从未来补全。

主持人公开票型文字保留警长加权票，转换器以引擎公开的结果字段为准，不按一人一票重新计算。竞选票作为公开公告，普通放逐票另外结构化；平票未决的轮次不生成快照。猎人公开翻牌即作为已确认身份，即便没有开枪；开枪目标不会被确认为任何身份。除显式白名单字段外，源 metadata 不进入模型输入。

## 测试与试点

11 局离线 Mock 转成 30 个快照，仅用于检查输入格式和截止；不是正式评价数据。早期 `wolfgame_mock_v1` 缺少公开座位映射，仅留作历史产物，不应使用；修正后的数据为 `data/independent/wolfgame_mock_v2/`。

首次两次真实模型生成试点因强制 JSON 模式返回双重编码字符串、null 或无效 JSON，已中断且不用于评价，未完成的请求可能计费。对两条失败上下文作小规模接口对照：强制 JSON 均无法解析为对象，取消后均可解析；这不足以推广为模型普遍行为。第三方引擎的本地副本增加至多一层 JSON 解码，并在 `config/model_profiles_qwen35_local.json` 取消 response_format，仍保留 JSON object 和后续字段校验。修改不是上游功能。

本地兼容配置下生成一局一天的合成试点；46 条引擎交互记录成功，统计到 70 次底层请求，记录的输入 497021、输出 18508 token；公开发言中未出现引擎的异常兜底文本。统计来自日志，实际账单和已中断请求另计。转换得到 1 个快照；一次关闭思考的直接预测调用正常结束，角色配额合法、7/9 正确。该数字只验证流水线可以执行，不能作为正式效果。试点标签、输入和结果分别位于 `data/independent/wolfgame_llm_pilot_v3/` 和 `outputs/metrics/wolfgame_synthetic_pilot_direct_v1.json`，勿与原数据集混用。

本地 21 项测试通过，覆盖截止前后信息隔离、标签和终局存活状态不影响输入、平票不产生快照、公开猎人翻牌掩码以及已有基线。仍需人工完整核验真实生成日志、警长和投票规则、早期终局/平票/无枪场景，以及更大且多来源的独立对局；不要用 Mock 或此试点宣称性能改善。
